# 운영 방법

## 하루의 단위

실행 단위는 `plan/days/Dxx.md` 한 장이다. 그 파일만 읽어도 오늘 할 일, 요구사항, 테스트, 완료 조건이 닫혀 있어야 한다.

파일을 열면 위에서부터 본다.

1. 오늘 끝나야 보이는 것
2. 데모 순서
3. 혼자 할 때 / 나눠 할 때
4. 트랙별 WBS
5. 테스트
6. 완료 조건
7. 하루 끝 기록

## 혼자 할 때

그날 파일의 **혼자 할 때** 순서를 따른다. 보통 트랙 A로 화면을 먼저 고정하고, 이어서 트랙 B를 붙인다. 트랙 C는 남은 시간에 샘플과 기록을 채운다. 트랙 D는 적힌 시간상자를 넘기면 결과만 남기고 중단한다.

화면이 아직 없으면 다른 트랙을 더 하지 않는다. 예외는 D09이다. 이 날은 한컴에서 파일을 확인하는 날이므로 새 화면 기능을 열지 않는다.

## 나눠 할 때

하루 파일의 **나눠 할 때**에 트랙별 지시 문장이 있다. 그 문장을 담당자에게 그대로 준다.

트랙이 만지는 디렉터리는 고정이다.

| 트랙 | 디렉터리 | 하는 일 |
|---|---|---|
| A 화면 | `apps/web` | 업로드, 표시, 선택, 미리보기, 승인 조작 |
| B 명령 | `packages/commands`, `packages/hwpx` | 스키마, 검증, 초안, 패치, 저장 |
| C 호환 | `corpus`, `tools/corpus`, `notes/hancom` | 샘플, ZIP 검사, 한컴 기록 |
| D 엔진 | `notes/engines` | 시간상자 안의 오픈소스 확인 |

같은 파일을 두 트랙이 고치지 않는다. 화면이 명령 함수를 부를 때는 이미 있는 export만 사용한다. 함수가 아직 없으면 A는 자리와 더미 표시를 만들고, B가 export를 추가한 뒤 A가 연결한다. 연결 순서가 그날 파일에 적혀 있다.

## 보이는 것의 기준

하루의 완료는 문서가 늘어난 것이 아니다. 데모 순서를 한 번 실행해서 화면에 나온 결과를 기록란에 적는다. 테스트 명령의 통과 여부도 같이 적는다.

내부 구조만 바뀌는 날에도, 화면에 상태 문장이 보여야 한다. 예: `바꿀 파트: Contents/section0.xml`, `받은 파일은 아직 그대로`, `MIXED_RUNS로 저장을 막음`.

## 게이트

- D03이 끝나야 승인 전 원본이 안 바뀐다는 것을 데모할 수 있다.

## 기록

비밀이 적힌 문서, API 키, 개인 파일은 커밋하지 않는다. 한컴 확인 결과에는 파일 이름, 한글 버전, 성공/실패, 막힌 단계를 적는다. 본문 전문을 붙이지 않는다.
