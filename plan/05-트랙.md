# 병렬 트랙

## A 화면

담당 디렉터리: `apps/web`

업로드, 문단 목록, 페이지 칸, 선택 강조, 바꿀 문장 입력, 나란히 비교, 승인/거절, 다운로드 버튼, 오류 문장.

데이터는 B가 export한 함수의 반환값만 표시한다. XML을 화면 컴포넌트 안에서 고치지 않는다.

## B 명령과 패키지

담당 디렉터리: `packages/commands`, `packages/hwpx`

스키마, 초안 생성, 검증, 문서 모델, ZIP 읽기, 원본 바이트 보관, 대상 XML 패치, 결과 ZIP 생성.

React에 의존하지 않는다. 테스트는 Vitest로 브라우저 없이 돈다.

## C 호환

담당 디렉터리: `corpus`, `tools/corpus`, `notes/hancom`

샘플 정의, 엔트리 목록 스크립트, 패치 전후 엔트리 비교, 한컴 확인 기록.

C의 스크립트 실패가 A의 화면 완료를 지우지는 않는다. 다만 D06 이후의 저장 완료는 C의 바이트 비교가 통과해야 닫힌다. D09의 완료는 한컴 기록이 있어야 닫힌다.

## D 엔진 비교

담당 디렉터리: `notes/engines`

`edwardkim/rhwp`, `airmang/python-hwpx`를 시간상자 안에서 확인한다. 빌드가 막히면 기록하고 중단한다. 화면 스택은 D01에서 정한 React, TypeScript, Vite, fflate, Vitest를 유지한다.

D03이 끝날 때 메모 한 장을 남긴다. 채택이 바뀌어도 D04 이후에 갈아타려면, 이미 데모되는 업로드와 명령 흐름이 같은 날에 다시 보여야 한다. 메모만으로 스택을 바꾸지 않는다.

## 충돌을 피하는 파일 경계

| 경로 | 주인 |
|---|---|
| `apps/web/**` | A |
| `packages/commands/**` | B |
| `packages/hwpx/**` | B |
| `tools/corpus/**` | C |
| `corpus/**` | C |
| `notes/hancom/**` | C |
| `notes/engines/**` | D |
| `pnpm-workspace.yaml`, 루트 `package.json` | D01의 A가 만들고, 이후에는 그날 파일에 적힌 트랙만 고친다 |

공유 타입이 필요하면 `packages/commands`에 두고 A가 import한다. A에서 타입을 새로 정의하지 않는다.
