# 원칙

1. **HWPX가 원본 데이터다.** 자체 포맷을 최종 저장 포맷으로 두지 않는다.
2. **화면은 우리가 그린 SVG다.** 문서는 `<svg>`로 표시하고, 그 SVG를 HWPX로 되돌리지 않는다. [rhwp](https://github.com/edwardkim/rhwp)는 페이지 단위 배치를 볼 때의 참고이며, 런타임으로 넣지 않는다. 기준은 [뷰어](06-뷰어.md)다.
3. **수정은 허용된 명령만 한다.** ZIP/XML 전체를 자유 형식으로 다시 쓰지 않는다.
4. **문서 엔진이 고친다.** 검증을 통과한 명령만 XML에 적용한다.
5. **한컴 한글 호환이 완료 조건이다.** 우리 화면에서 보이는 것만으로 성공으로 치지 않는다.
6. **원본을 보존한다.** 받은 파일을 덮어쓰지 않는다. 바꾸지 않은 ZIP 엔트리는 원본 바이트를 복사한다.
7. **먼저 보이게 한다.** 엔진 비교와 라이선스 실사가 첫 화면을 막지 않는다. 실사는 시간상자와 출시 전 카드로 분리한다.
8. **붙일 자리를 먼저 만든다.** 선택 결과와 편집 명령의 입출력이 고정되면, 그 자리를 사람이 쓰든 바깥 모델이 쓰든 같은 검증과 같은 패치를 탄다.

## 초기 명령

먼저 구현하는 명령은 세 가지다.

- `replace_text`
- `rewrite_paragraph`
- `replace_cell_text`

`rewrite_paragraph`와 텍스트 교체는 문단 또는 칸의 텍스트 런이 하나일 때만 자동 적용한다. 런이 여러 개이면 `MIXED_RUNS`로 거절하고 화면에 이유를 보인다. 서식을 지우면서 문장을 합치지 않기 위해서다.

후속 카드로 남기는 명령은 문단 삽입/삭제, 스타일 변경, 표 행/열, 이미지 교체다. 스타일 변경은 참조 관계를 깨기 쉬우므로 기본 보류다. [WP-03](backlog/WP-03-style.md)에서 허용 조건을 정하기 전에는 구현하지 않는다.

## 노드 식별

`node_id`는 이 앱의 식별자다. HWPX 문단의 `id` 속성을 `node_id`로 쓰지 않는다. 그 속성은 원본 값으로 유지한다.

형식은 `section{번호}_p{문단인덱스}`와 `section{번호}_p{문단인덱스}_c{행}_{열}`이다. 패키지 엔트리 경로, XML에서 찾은 위치, 원문 텍스트를 함께 저장한다. 문단을 읽을 때 런 목록과 `paraPrIDRef`, 각 런의 `charPrIDRef`를 함께 둔다. 글자 모양은 `header.xml`에 있고 본문은 그 번호만 가진다. 근거는 [HWPX 포맷](hwpx-포맷.md)이다. 원문이 명령의 `expected_original_text`와 다르면 적용하지 않는다.

화면 좌표는 대상을 찾는 보조 정보다. 패치가 사용하는 대상은 `node_id`와 원문이다.

## 저장

임시 결과물을 만들고, 패키지 검사와 명령 검사를 통과한 뒤에만 다운로드용 바이트를 확정한다. 사용자의 원본 경로에 쓰지 않는다.
