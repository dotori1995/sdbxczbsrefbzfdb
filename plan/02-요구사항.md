# 요구사항

수치는 D09 전후에 코퍼스를 재면서 정한다. 측정 전에 호환률 100%를 목표 수치로 적지 않는다.

## 화면

| ID | 요구 | 처음 닫히는 날 |
|---|---|---|
| R-VIS-01 | HWPX를 올리면 문단이 SVG 페이지 안에 문서 순서로 보인다 | D01 |
| R-VIS-02 | 손상된 ZIP은 빈 화면 없이 오류로 보인다 | D01 |
| R-VIS-03 | SVG 페이지가 A4 크기를 가지고, 문단이 줄 단위 `<text>`로 나뉘며 `data-node-id`가 있다 | D05 |
| R-VIS-04 | `tbl`의 행과 칸, `cellAddr`, `cellSpan`, `cellSz`, 칸 글자, 칸 안 그림이 격자로 보인다. 칸 글자 수정은 D08이다 | [D17](days/D17.md) |
| R-VIS-05 | 본문 `pic`와 manifest의 BinData를 연결해 그린다. 크기는 `curSz`, 없으면 `orgSz`다. 없는 그림 요소는 만들지 않는다 | [D16](days/D16.md) |
| R-VIS-06 | 확대와 축소 뒤에도 같은 선택이 유지된다 | D11 |
| R-VIS-07 | 문단에 `linesegarray`가 있으면 화면 줄은 그 줄의 `vertpos`, `horzpos`, `horzsize`, `textpos`, `baseline`을 쓴다. 캐시가 없으면 16px/8px, 너비 710px다. 없는 캐시는 계산해 넣지 않는다 | [D18](days/D18.md) |

화면이 문서를 보여 준다. 쪽 여백은 [WP-03](backlog/WP-03-style.md)에 있다. 그림, 표 격자, 파일에 있는 줄 위치의 다음 화면은 [D16](days/D16.md), [D17](days/D17.md), [D18](days/D18.md)이다. `cellAddr`, `cellSpan`, `cellSz`, `subList`는 구현 문서의 관찰이다. `linesegarray`는 OWPML이 아니라 한글 레이아웃 캐시다. D05의 근사치는 그 캐시가 없을 때의 대체로 남는다. 칸 안 문단을 바깥 본문 문단 글자에 펼쳐 넣지 않고 본문 문단 목록에서 빼 두는 현재 읽기 규칙은 유지한다. 화면에서만 표로 보인다. D08은 칸 글자 수정이다. D07 다운로드는 이 화면 작업이 아니다. 한컴과 줄바꿈이 같다고 두지 않는다. 한컴과 같은 조판이 끝났다고 두지 않는다.
