# D12. 이미지가 빠지지 않고 자리가 보인다

## 오늘 끝나야 보이는 것

T04에서 이미지 바이트가 있으면 페이지에 그림이 보인다. 참조만 있고 바이트가 없으면 파일 이름과 경고가 보인다. 문단을 수정해 저장해도 `BinData` 엔트리 해시는 원본과 같다.

## 데모 순서

1. 이미지가 들어 있는 fixture를 연다.
2. 그림 또는 자리 상자가 문단과 함께 보인다.
3. 문단 텍스트만 바꾸고 새 파일을 받는다.
4. 비교 도구에서 `BinData` 해시가 같다.
5. 바이트를 뺀 fixture를 연다.
6. 경고 문장이 보이고, 문단 수정 저장은 D15 전까지는 허용하되 경고가 남는다. 저장 차단은 D15에서 정책이 닫힌다.

## 혼자 할 때

B가 이미지 참조와 엔트리 보존 테스트를 고정한다. A가 자리 표시를 그린다. C가 비교 도구로 BinData를 확인한다.

## 나눠 할 때

- B: `이미지 모델과 보존 테스트만 추가한다. 이미지 교체 명령은 넣지 않는다.`
- A: `이미지 표시만 추가한다.`
- C: `T04 비교 결과를 notes/hancom/D12-bindata.md에 적는다.`

## 트랙 B — 보존 (필수)

### WBS

1. fixture ZIP에 `BinData` 이미지 하나를 넣는다.
2. 모델이 참조 경로와 엔트리 존재 여부를 반환한다.
3. 문단 패치 후 그 엔트리 해시가 같은 테스트를 둔다.
4. 엔트리가 없는 참조 fixture를 하나 둔다.
5. 이미지 바이트를 재인코딩하는 코드를 넣지 않는다.

### 테스트

- 패치 후 BinData SHA-256 동일
- 누락 참조는 모델의 경고 코드 `MISSING_BINDATA`

### 완료

- [ ] 테스트 통과

## 트랙 A — 화면 (필수)

### WBS

1. 참조가 살아 있으면 이미지로 표시한다.
2. 없으면 상자에 경로와 `이미지 바이트가 없습니다`를 보인다.
3. 상자를 클릭하면 대상 JSON의 `kind`가 `image`다.
4. 이미지 대상에는 문장 입력칸을 비활성화하고 `텍스트 명령 대상이 아닙니다`를 보인다.

### 완료

- [ ] 데모 1–6

## 트랙 C — 기록 (2시간)

### WBS

1. 결과 ZIP 비교를 실행한다.
2. 로컬 한컴 이미지가 있으면 열기만 확인하고, 수정 저장 실험은 T01이 이미 성공한 경우에만 한다.
3. 결과를 `notes/hancom/D12-bindata.md`에 적는다.

### 완료

- [ ] 해시 비교 결과가 적혀 있다

## 막히면

미리보기가 실패하면 자리 상자와 해시 테스트를 완료로 인정한다. 그림 픽셀이 보여야만 저장 보존 테스트를 미루지 않는다.
