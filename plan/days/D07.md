## 오늘 끝나야 보이는 것

승인한 뒤에만 `새 파일 받기`가 활성화된다. 받은 파일 이름은 원본 이름에 `.edited.hwpx`가 붙은 형태다. 브라우저가 원본 파일을 덮어쓰지 않는다. 받은 파일을 다시 올리면 고친 문단이 보인다.

## 데모 순서

1. T01을 수정하고 승인한다.
2. `새 파일 받기`로 다운로드한다.
3. 원본 입력 파일의 수정 시각이 바뀌지 않았는지 파일 탐색기에서 본다.
4. 내려받은 파일을 앱에 다시 올린다.
5. 고친 문단이 보이고 다른 문단은 그대로다.
6. 승인 전에 버튼이 비활성이다.

## 혼자 할 때

B의 writer 테스트를 통과시킨 뒤 A의 버튼을 연결한다. C는 writer 결과에 인벤토리 비교를 돌린다.

## 나눠 할 때

- B: `packages/hwpx/src/write 만 구현한다.`
- A: `apps/web의 다운로드 버튼만 연결한다. writer 내부를 복붙하지 않는다.`
- C: `결과 ZIP에 tools/corpus 비교를 실행하고 메모를 남긴다.`

## 트랙 B — 쓰기 (필수)

### WBS

1. 패치 계획을 ZIP 바이트로 만든다.
2. `mimetype`은 첫 엔트리이고 압축하지 않는다. 테스트로 압축 방식을 확인한다.
3. 유지 엔트리는 원본 바이트를 그대로 넣는다.
4. 변경 엔트리만 새 바이트를 넣는다.
5. 메모리에서 ZIP을 완성한 뒤에만 반환한다. 실패하면 바이트를 반환하지 않는다.
6. API는 `buildEditedPackage(originalBytes, command)` 하나다.

### 테스트

- 승인되지 않은 호출 경로는 UI 책임이다. 함수는 검증 실패 시 throw하거나 오류를 반환하고 바이트를 주지 않는다.
- `mimetype`이 stored다.
- 왕복 `readParagraphs`가 수정 문단을 읽는다.
- 더미 엔트리 해시가 같다.

### 완료

- [ ] 테스트 통과
