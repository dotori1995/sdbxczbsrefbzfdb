## 오늘 끝나야 보이는 것

배율 100%, 150%, 50%에서 같은 드래그의 `node_id`와 `text_range`가 같다. 배율을 바꾼 뒤에도 강조가 다른 문단으로 옮겨 가지 않는다.

## 데모 순서

1. T11에서 두 번째 문단의 같은 세 글자를 100%에서 고른다.
2. 150%로 바꾼다. 강조와 JSON이 유지된다.
3. 선택을 해제하고 같은 세 글자를 다시 드래그한다. 범위가 같다.
4. 50%에서 3을 반복한다.
5. 페이지 칸이 잘려 보이지 않으면 가로 스크롤로 칸 전체를 도달할 수 있다.

## 혼자 할 때

A가 배율과 히트 테스트를 고친다. B는 1시간 안에 순수 함수 `indexFromX` 테스트만 보강한다. 이미 범위 패치가 있으면 패키지 수정은 최소화한다.

## 나눠 할 때

- A: `apps/web의 페이지 배율과 selection만 수정한다.`
- B: `packages/hwpx에 화면 좌표를 넣지 않는다. 문자 인덱스 계산이 화면 밖에 있으면 packages가 아니라 apps/web/src/selection/metrics.ts로 둔다.`

## 트랙 A — 화면 (필수)

### WBS

1. 페이지 칸에 배율 100, 150, 50 버튼을 둔다.
2. 히트 테스트가 배율이 적용된 사각형을 기준으로 인덱스를 계산하게 한다.
3. 배율 변경 시 기존 `text_range`를 유지한다.
4. 칸 밖에 점이 떨어지면 선택을 바꾸지 않는다.
5. 데모 1–5를 실행한다.

### 완료

- [ ] 세 배율의 `text_range`가 기록란에 같고 기대와 같다

## 트랙 B — 인덱스 (1시간)

### WBS

1. 문자 너비 배열과 배율을 입력하면 인덱스를 반환하는 함수를 selection 모듈에 둔다.
2. 경계 클릭, 왼쪽 밖, 오른쪽 밖 테스트를 둔다.
3. DOM이 없는 단위 테스트로 고정한다.

### 테스트

- 배율 1과 1.5에서 같은 논리 인덱스가 나온다
- 영역 밖은 선택 변경 없음으로 표현되는 값을 반환한다

### 완료

- [ ] 테스트 통과

## 막히면

폰트 메트릭 라이브러리를 오늘 도입하지 않는다. 고정 폭 추정으로 데모가 흔들리면 글자 DOM을 글자마다 감싸 인덱스와 1:1로 대응한다. 그 방식이 오늘 완료로 더 가깝다.
