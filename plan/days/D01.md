## 오늘 끝나야 보이는 것

HWPX를 올리면 문단 문자열이 위에서 아래 순서로 보인다. 손상된 파일은 오류 문장이 보인다.

## 데모 순서

1. `pnpm dev`로 앱을 연다.
2. T01 fixture를 올린다.
3. 문단 두 줄이 보인다.
4. 확장자만 바꾼 빈 파일을 올린다.
5. 목록이 비어 있는 상태가 아니라 오류 문장이 보인다.

## 혼자 할 때

A를 끝내 데모 1–3을 고정한다. 이어서 B의 예시 JSON이 같은 화면에 보이게 한다. C와 D는 각 2시간을 넘기면 기록만 남긴다.

## 나눠 할 때

- A: `D01 트랙 A만 한다. apps/web만 수정한다. 문단 추출이 필요하면 packages/hwpx에 이미 있는 export만 쓴다. 없으면 화면용 임시 추출을 apps/web/src/extract.ts에 두고 B가 바꿀 수 있게 함수 이름을 적는다.`
- B: `D01 트랙 B만 한다. packages/commands와 packages/hwpx만 수정한다. replace_text 스키마와 fixture ZIP 문단 추출 테스트를 넣는다.`
- C: `D01 트랙 C만 한다. corpus 문서와 gitignore만 수정한다. 2시간을 넘기지 않는다.`
- D: `D01 트랙 D만 한다. notes/engines/rhwp.md만 작성한다. 2시간을 넘기면 빌드를 중단하고 막힌 명령을 적는다.`

A와 B가 추출 함수를 같이 만들면 충돌한다. B가 `packages/hwpx`의 `readParagraphs`를 먼저 두고, A는 그 함수만 호출한다. 혼자면 B의 추출을 먼저 30분 안에 테스트로 고정한 뒤 화면에 연결한다.

## 트랙 A — 화면 (필수)

### WBS

1. pnpm 워크스페이스를 만든다. `apps/web`, `packages/commands`, `packages/hwpx`, `tools/corpus`.
2. Vite, React, TypeScript 앱을 띄운다.
3. 파일 입력으로 `.hwpx`를 받는다.
4. `readParagraphs` 결과를 문서 순서대로 그린다.
5. 예외는 `파일을 열 수 없습니다`와 원인 한 줄을 화면에 쓴다.
6. 예시 명령 JSON을 옆 패널에 텍스트로 보여 준다. 적용 버튼은 만들지 않는다.

### 손대는 곳

- `apps/web`
- 루트 `package.json`, `pnpm-workspace.yaml` (이 날의 A만)

### 완료

- [ ] 데모 1–5
- [ ] 적용 버튼, 저장 버튼이 없다

## 트랙 B — 명령 (필수)

### WBS

1. `replace_text` 타입과 파서를 둔다. 허용 필드는 [연결 경계](../04-연결-경계.md)의 명령 JSON이다.
2. 알 수 없는 `command` 값은 오류로 반환한다.
3. 테스트용 T01 ZIP을 코드로 만든다. `mimetype`, `Contents/section0.xml`, 문단 둘.
4. `readParagraphs`가 `[{ nodeId: "section0_p0", text }, { nodeId: "section0_p1", text }]`를 반환하는 테스트를 통과시킨다.
5. 예시 객체를 `exampleReplaceText`로 export한다.

문단 태그는 fixture XML에 맞춘다. 네임스페이스가 달라도 텍스트 노드를 문서 순서로 모으는 테스트를 하나 더 둔다. 한컴 실파일의 태그 차이는 D02 트랙 C가 인벤토리로 확인한다.

### 손대는 곳

- `packages/commands`
- `packages/hwpx`

### 테스트

- `pnpm test`
- fixture 문단 수와 문자열이 기대와 같다
- `command: "delete_document"`는 거절된다

### 완료

- [ ] 위 테스트가 통과한다
- [ ] 화면 컴포넌트를 import하지 않는다
