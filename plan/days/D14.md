## 오늘 끝나야 보이는 것

명령 JSON을 붙여 넣으면 D02와 같은 검증 문장이 보이고, 통과하면 D03의 비교와 D07의 다운로드로 이어진다. 모델 호출 버튼은 없다.

## 데모 순서

1. 문맥을 복사한다.
2. 사람이 그 값으로 `replace_text` JSON을 만든다. 앱 밖에서 만든다.
3. 붙여넣기 칸에 넣는다.
4. 검증 통과와 나란히 비교가 보인다.
5. 승인 후 새 파일을 받는다.
6. 다시 올리면 그 문장만 바뀌어 있다.
7. `command`를 허용 목록 밖으로 바꾸면 비교와 다운로드가 사라진다.

## 혼자 할 때

B의 `ManualJsonPlanner`와 파서 테스트를 먼저 둔다. A는 칸과 기존 승인 패널을 연결한다. `ModelPlanner` 스텁을 마지막에 넣는다.

## 나눠 할 때

- B: `packages/commands의 planner만 추가한다. fetch와 API 키를 넣지 않는다.`
- A: `붙여넣기 칸만 추가하고 기존 preview 컴포넌트를 재사용한다.`

## 트랙 B — 플래너 (필수)

### WBS

1. `EditPlanner` 타입을 [연결 경계](../04-연결-경계.md)와 같이 둔다.
2. `ManualJsonPlanner`는 문자열을 파싱해 `validateCommand`에 넘긴다.
3. JSON이 배열이면 명령을 순서대로 검증한다. 하나라도 실패하면 전체 결과를 실패로 반환하고 적용 목록을 비운다.
4. `ModelPlanner.plan`은 거부 오류만 반환한다. 오류 문장은 `모델 연결은 이 저장소의 완료 범위 밖`이다.
5. 입력칸 초안 경로는 `ManualTextPlanner` 이름으로 D02 함수를 감싼다. 동작은 유지한다.

### 테스트

- 정상 JSON 하나 통과
- 깨진 JSON 실패
- 배열 중 두 번째가 `STALE_TEXT`면 적용 목록이 비어 있다
- ModelPlanner가 거부한다

### 완료

- [ ] 테스트 통과
- [ ] 의존성에 모델 SDK가 없다

## 트랙 A — 화면 (필수)

### WBS

1. 명령 JSON 입력칸을 둔다.
2. `검증`을 누르면 planner 결과를 기존 비교 패널에 넣는다.
3. 여러 명령이 통과하면 비교를 명령 수만큼 나열한다.
4. 승인 한 번이 통과한 명령 묶음에 적용된다. 일부만 적용하는 경로는 두지 않는다.
5. 모델 이름, API 키 입력, 보내기 버튼을 두지 않는다.

### 완료

- [ ] 데모 1–7
