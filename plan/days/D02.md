## 오늘 끝나야 보이는 것

SVG의 문단 `<text>`를 클릭하면 그 요소가 강조되고, 선택 JSON이 보인다. 바꿀 문장을 적으면 검증 결과가 `통과` 또는 사유와 함께 보인다. 통과 전에는 적용 조작이 없다.

## 데모 순서

1. T01을 올린다.
2. 두 번째 문단을 클릭한다.
3. 패널의 `node_id`가 `section0_p1`이다.
4. 바꿀 문장에 `수정한 문단이다`를 입력한다.
5. 명령 JSON의 `expected_original_text`가 현재 문단과 같고, 검증이 통과한다.
6. 명령의 `command`를 임의 값으로 바꾸면 통과가 사라진다.

## 혼자 할 때

B의 `draftReplaceText`와 `validateCommand`를 테스트로 고정한 뒤 A에 연결한다. C는 2시간, D는 2시간.

## 나눠 할 때

- A: `apps/web만 수정한다. draftReplaceText와 validateCommand를 호출해 선택과 검증 결과를 그린다. 패키지 구현은 바꾸지 않는다.`
- B: `packages/commands와 필요한 모델 타입만 수정한다. 화면을 만들지 않는다.`
- C: `tools/corpus만 수정한다. ZIP 인벤토리 스크립트를 만든다.`
- D: `notes/engines/python-hwpx.md만 작성한다. 2시간을 넘기지 않는다.`

## 트랙 A — 화면 (필수)

### WBS

1. SVG `<text>` 클릭으로 선택 상태를 둔다.
2. 선택된 `<text>`만 강조한다. 강조는 본문 텍스트 노드 위의 `<rect>`다.
3. `node_id`, 엔트리 경로, 원문을 패널에 표시한다.
4. 바꿀 문장 입력칸을 둔다.
5. 입력이 바뀔 때마다 초안을 만들고 검증 결과만 표시한다.
6. 적용, 저장, 다운로드 컨트롤을 두지 않는다.

### 완료

- [ ] 데모 1–6
- [ ] 선택을 바꾸면 이전 문단의 강조가 빠진다

## 트랙 B — 명령 (필수)

### WBS

1. `draftReplaceText(selection, replacementText)`가 `replace_text` 객체를 반환한다.
2. `requires_confirmation`은 `true`로 둔다.
3. `validateCommand`가 다음을 검사한다.
   - 명령 이름이 허용 목록에 있는지
   - `target_node_id`가 현재 문서에 있는지
   - `expected_original_text`가 그 노드의 현재 텍스트와 같은지
   - `requires_confirmation`이 `true`인지
4. 실패 시 기계가 읽을 수 있는 코드와 사람용 문장을 반환한다. 코드 예: `UNKNOWN_COMMAND`, `MISSING_TARGET`, `STALE_TEXT`.
5. 테스트를 위 네 가지에 대해 각각 둔다.

### 테스트

- `pnpm test`
- 정상 초안은 통과한다
- 빈 대상, 다른 원문, 알 수 없는 명령은 각각 다른 코드로 실패한다

### 완료

- [ ] 테스트 통과
- [ ] 검증 함수가 문서를 수정하지 않는다
