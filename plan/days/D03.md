## 오늘 끝나야 보이는 것

검증을 통과한 명령이 원문과 수정안을 나란히 보여 준다. 승인 버튼과 거절 버튼이 있다. 승인해도 받은 파일과 SVG 문단의 원문은 바뀌지 않고, `파일은 아직 그대로`가 보인다. 다운로드는 없다.

## 데모 순서

1. 두 번째 문단을 고르고 바꿀 문장을 입력한다.
2. 왼쪽에 현재 문장, 오른쪽에 바꿀 문장이 보인다.
3. 거절을 누르면 비교가 사라지고 선택은 유지된다.
4. 다시 초안을 만든 뒤 승인을 누른다.
5. SVG의 글자는 그대로이고 상태 문장이 `파일은 아직 그대로`다.
6. 페이지를 새로고침하기 전의 원본 파일 바이트가 업로드 때와 같다. 앱은 그 파일을 쓰지 않는다.

## 혼자 할 때

A로 비교 UI와 상태 전이를 만든다. B는 승인 상태를 표현하는 순수 함수만 추가한다. C는 한컴에서 T01을 열어 보는 체크리스트를 적는다. D는 D01–D02 메모를 한 장으로 모으고 오늘로 끝낸다.

## 나눠 할 때

- A: `apps/web만 수정한다. 승인 뒤에도 readParagraphs 결과를 다시 그리지 않는다.`
- B: `packages/commands에 preview 상태 전이만 추가한다. ZIP 쓰기는 넣지 않는다.`
- C: `notes/hancom/open-checklist.md만 작성한다.`
- D: `notes/engines/decision.md만 작성한다. 앱 의존성을 바꾸지 않는다.`

## 트랙 A — 화면 (필수)

### WBS

1. 검증 통과 후에만 비교 영역을 연다.
2. 승인, 거절 버튼을 둔다.
3. 상태를 `draft`, `valid`, `invalid`, `approved`, `rejected` 중 화면에 맞는 이름으로 보여 준다.
4. `approved`여도 SVG 텍스트는 업로드 시점 모델을 유지한다.
5. `파일은 아직 그대로`를 `approved`일 때 표시한다.
6. 다운로드 컨트롤을 두지 않는다.

### 완료

- [x] 데모 1–6

## 트랙 B — 명령 (필수)

### WBS

1. `previewDecision(state, action)` 순수 함수를 둔다.
2. `approve`는 `valid`에서만 `approved`가 된다.
3. `reject`는 비교용 명령을 비운다.
4. 함수가 문서 모델과 ZIP 바이트를 인자로 받아 수정하지 않는 테스트를 둔다. 호출 전후 참조가 같으면 된다.

### 테스트

- invalid에서 approve는 상태가 바뀌지 않는다
- approve 호출 전후 문단 배열의 문자열이 같다

### 완료
