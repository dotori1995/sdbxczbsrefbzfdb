## 오늘 끝나야 보이는 것

긴 목록 대신, 페이지처럼 보이는 칸 안에 문단이 들어 있다. 각 문단 DOM에 `data-node-id`가 있다. 클릭하면 D02와 같은 선택 JSON이 나온다.

한컴과 줄바꿈이 달라도 오늘은 완료로 친다. 차이를 `notes/layout-gaps.md`에 적는다.

## 데모 순서

1. T01을 연다.
2. 흰 페이지 칸 안에 문단 두 개가 보인다.
3. 개발자 도구에서 각 문단의 `data-node-id`를 확인한다.
4. 문단을 클릭하면 D02와 같은 패널이 채워진다.
5. 승인 흐름은 D04와 같이 그 문단 텍스트만 칸 안에서 바뀐다.

## 혼자 할 때

A를 먼저 닫는다. B는 2시간 안에 `rewrite_paragraph` 스키마만 추가한다. 적용 규칙은 `replace_text`와 같고 단일 런만 허용한다. C는 2시간 안에 T03 표 샘플 정의만 적는다.

## 나눠 할 때

- A: `apps/web/src/page 만 새로 만든다. 명령 패키지는 수정하지 않는다.`
- B: `packages/commands의 스키마와 테스트만 수정한다. rewrite_paragraph는 단일 런 검증만 통과시키고 XML 쓰기는 하지 않는다.`
- C: `corpus 문서에 T03 기대 칸 텍스트를 적는다.`

D04와 같은 날에 병렬로 할 때는 A 담당을 나눈다. 한 사람은 목록 적용, 한 사람은 페이지 칸.

## 트랙 A — 화면 (필수)

### WBS

1. 페이지 칸 컴포넌트를 만든다. 종이 비율만 맞추고 여백은 고정값으로 둔다.
2. 문단을 칸 안에 블록으로 배치한다. 글꼴은 시스템 한글 폰트 fallback이다.
3. 블록에 `data-node-id`를 넣는다.
4. 기존 클릭 선택을 이 블록에 연결한다.
5. 목록 화면은 제거하거나 페이지 화면 뒤로 둔다. 데모의 기본 화면은 페이지다.
6. 눈으로 본 줄바꿈 차이를 `notes/layout-gaps.md`에 적는다.

### 완료

- [ ] 데모 1–5
- [ ] 노드가 없는 문단 블록이 없다

## 트랙 B — 스키마 (2시간)

### WBS

1. `rewrite_paragraph`를 허용 목록에 넣는다.
2. 필드 형태는 `replace_text`와 같게 한다.
3. 단일 런이 아니면 `MIXED_RUNS`다.
4. 런이 하나면 검증이 통과한다.
5. 이 명령의 ZIP 적용은 D06 이후로 미룬다. 오늘은 검증까지만이다.

### 테스트

- 허용 명령 목록에 둘 다 있다
- 혼합 런 `rewrite_paragraph`는 거절된다

### 완료

- [ ] 테스트 통과
