## 오늘 끝나야 보이는 것

D01의 SVG가 페이지 높이를 가지고, 긴 문단은 줄마다 `<text>`로 나뉜다. 각 줄은 같은 `data-node-id`를 가진다. 클릭하면 D02와 같은 선택 JSON이 나온다.

한컴과 줄바꿈이 달라도 오늘은 완료로 친다. 차이를 `notes/layout-gaps.md`에 적는다. HTML 페이지로 바꾸지 않는다. rhwp 코드는 붙이지 않는다.

## 데모 순서

1. T01을 연다.
2. `<svg>`의 너비는 794, 높이는 1123이다. 문단 두 개가 그 안에 보인다.
3. 개발자 도구에서 각 문단의 `data-node-id`를 확인한다.
4. 문단을 클릭하면 D02와 같은 패널이 채워진다.
5. 승인 흐름은 D04와 같이 그 문단의 `<text>`만 바뀐다.

## 혼자 할 때

A를 먼저 닫는다. B는 2시간 안에 `rewrite_paragraph` 스키마만 추가한다. 적용 규칙은 `replace_text`와 같고 단일 런만 허용한다. C는 2시간 안에 T03 표 샘플 정의만 적는다.

## 나눠 할 때

- A: `apps/web/src/svg 만 수정한다. 명령 패키지는 수정하지 않는다.`
- B: `packages/commands의 스키마와 테스트만 수정한다. rewrite_paragraph는 단일 런 검증만 통과시키고 XML 쓰기는 하지 않는다.`
- C: `corpus 문서에 T03 기대 칸 텍스트를 적는다.`

D04와 같은 날에 병렬로 할 때는 A 담당을 나눈다. 한 사람은 텍스트 갱신, 한 사람은 줄 배치.

## 트랙 A — 화면 (필수)

### WBS

1. 페이지 `<svg>`를 794×1123으로 둔다. 넘치는 문단은 다음 `<svg>`로 넘긴다.
2. 문단 문자열을 내용 너비에 맞춰 줄로 나누고, 줄마다 `<text>`를 둔다. 같은 문단은 같은 `data-node-id`와 `data-line`을 가진다.
3. 글꼴은 시스템 한글 폰트다. 줄 높이의 초기값은 28px이다.
4. 클릭 선택을 이 `<text>`에 유지한다.
5. 선택 `<rect>`는 텍스트 그룹과 다른 그룹에 둔다.
6. 눈으로 본 줄바꿈 차이를 `notes/layout-gaps.md`에 적는다. rhwp에서 본 페이지 단위 배치와 다른 점도 한 줄 적는다.

### 완료

- [ ] 데모 1–5
- [ ] 문단 글자가 `<text>` 밖에 없다

## 트랙 B — 스키마 (2시간)

### WBS

1. `rewrite_paragraph`를 허용 목록에 넣는다.

3. 단일 런이 아니면 `MIXED_RUNS`다.
4. 런이 하나면 검증이 통과한다.
5. 이 명령의 ZIP 적용은 D06 이후로 미룬다. 오늘은 검증까지만이다.
