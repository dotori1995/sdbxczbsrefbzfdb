# 연결 경계

이 시스템이 받는 입력은 두 가지다.

1. 사용자가 고른 대상과, 입력칸에 적은 바꿀 문장
2. 허용된 명령 JSON

둘 다 `packages/commands`의 같은 검증을 통과한 뒤에 `packages/hwpx`가 적용한다.

## 인터페이스

구현 이름 후보는 아래다. D14에서 이 모양으로 고정한다.

```ts
interface EditPlanner {
  plan(input: PlanRequest): Promise<PlanResult>
}

interface PlanRequest {
  document_id: string
  instruction: string
  target: SelectionTarget
  context: ContextSlice
}

interface PlanResult {
  commands: EditCommand[]
}
```

완료에 포함하는 구현은 두 개다.

- `ManualTextPlanner`: 입력칸의 문장으로 `replace_text` 초안을 만든다. D02.
- `ManualJsonPlanner`: 붙여 넣은 JSON을 파싱해 검증기로 넘긴다. D14.

`ModelPlanner` 파일은 D14에 둔다. 호출하면 `모델 연결은 이 저장소의 완료 범위 밖`이라는 오류를 반환한다. 시그니처와 오류 문구가 곧 붙일 자리다. API 키, SDK, 프롬프트 문자열, 재시도 루프는 넣지 않는다.

## 문맥 JSON

D13에서 클립보드로 복사하는 값이다. 모델에 무엇을 보낼지의 최대 범위이기도 하다.

```json
{
  "document_id": "doc_01",
  "target": {
    "kind": "paragraph",
    "node_id": "section0_p1",
    "text_range": { "start": 0, "end": 12 },
    "selected_text": "원문 일부"
  },
  "neighbors": {
    "previous": "앞 문단 원문",
    "next": "다음 문단 원문"
  },
  "instruction": ""
}
```

문서 전체 모드에서는 `target.kind`가 `document`이고 `node_ids` 배열이 있다. 앱은 이 목록을 자동으로 고쳐 쓰지 않는다. 명령이 하나씩 검증을 통과해야 한다.

## 명령 JSON

```json
{
  "command": "replace_text",
  "target_node_id": "section0_p1",
  "expected_original_text": "원문 전체 또는 범위 원문",
  "replacement_text": "바꿀 문장",
  "text_range": { "start": 0, "end": 12 },
  "reason": "",
  "requires_confirmation": true
}
```

`requires_confirmation`이 `true`가 아니면 MVP 검증은 거절한다. 승인 버튼이 없는 적용 경로는 만들지 않는다.

## 바깥에서 붙이는 절차

1. 화면에서 대상을 고른다.
2. 문맥 JSON을 복사한다.
3. 바깥 도구가 명령 JSON을 만든다.
4. 그 JSON을 붙여넣기 칸에 넣는다.
5. 검증 결과가 화면에 나온다.
6. 승인하면 D07과 같은 저장 경로를 탄다.

이 여섯 단계가 D14 데모다. 단계 3의 도구는 이 계획에서 만들지 않는다.
