# WP-07. 긴 문서의 첫 화면이 빨리 나온다

- 상태: 시작 전
- 크기: 하루
- 착수: D05 이후
- 디렉터리: `apps/web`. 파서 전체를 다시 쓰지 않는다.

## 오늘 끝나야 보이는 것

문단이 많은 fixture에서 첫 페이지 칸이 먼저 보이고, 아래 문단은 스크롤할 때 채워진다. 선택과 패치 결과는 D05, D07과 같다.

## WBS

1. 문단 200개 fixture를 테스트로 만든다. 내용은 짧은 반복 문장이다.
2. 첫 화면 렌더에 모든 문단의 DOM을 만들지 않는다.
3. 스크롤 위치의 문단만 `data-node-id`를 가진다.
4. 화면 밖 문단을 명령 대상으로 고르려면 문서 전체 모드의 id 목록을 사용한다. 보이지 않는 DOM에 클릭을 요구하지 않는다.
5. 패치 후 해당 문단이 보이면 새 텍스트가 있다.

숫자는 이 날 측정해 `notes/layout-gaps.md`에 적는다. 예: 첫 칸이 보이기까지 걸린 시간. 목표 밀리초를 미리 단정하지 않는다.

## 테스트

- 200문단 fixture를 `readParagraphs`가 모두 반환한다
- 초기 DOM의 문단 노드 수가 한 페이지 분량 상한 이하다. 상한은 구현할 때 30 이하로 둔다
- 기존 T01 선택이 깨지지 않는다
